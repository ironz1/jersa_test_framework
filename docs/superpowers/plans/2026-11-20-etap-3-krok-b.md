# Etap 3, krok B: testy walidacji wejścia — plan wdrożenia

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Testy API i bazy dla poprawek walidacji wejścia sklepu (`b5e32c3`), żeby bramka pilnowała ich na każdym PR-ze sklepu.

**Architecture:** Testy dopisane do istniejących plików wg obszaru, jeden nowy plik na uszkodzony JSON (parametryzacja po endpointach). Jedna nowa funkcja w `jersa/db/products.py` (`set_hidden`) do ukrycia własnego produktu po dodaniu do koszyka. Każdy przypadek od razu w `docs/traceability.json`.

**Tech Stack:** pytest, requests (`ApiClient`), psycopg 3.

**Spec:** `docs/superpowers/specs/2026-11-19-etap-3-krok-b-design.md`

## Global Constraints

- Każdy test: marker `regression` (przez `pytestmark`), docstring zaczyna się od ID przypadku, wpis w `docs/traceability.json`.
- Własny produkt na test: `make_product(...)` / `product`; nigdy produkt z seeda. Ukrycie produktu tylko na własnym produkcie (`test-<hex>`).
- Komunikaty sklepu dosłownie, w kształcie `{"error": "..."}`, status 400.
- Nowe wymagania R35–R38, źródło `"właściciel sklepu, 2026-11-12/13"`. Uszkodzony JSON pod R13.
- Testy już przechodzą (zachowanie jest w sklepie), więc RED to kontrola mutacją: w jednym parametrze podmień oczekiwany komunikat na zły, uruchom, zobacz FAIL, przywróć.
- Sklep w Dockerze na `127.0.0.1:3100` (`main` sklepu, `f131eff`). Polecenia testów z `-n 0` dla pojedynczych plików.
- Nic o otwartych słabościach sklepu w plikach repo (ADR-014). Repo publiczne: bez ścieżek lokalnych i danych osobowych.

## Review Focus

1. Odrzucone żądanie nie zmienia koszyka: każdy test „400” w koszyku sprawdza też stan koszyka po odrzuceniu (zadbane w Task 2).
2. Ukryty produkt po dodaniu do koszyka: odrzucenie nie może zostawić zarezerwowanego stanu ani wiersza zamówienia (D-ORD-08 w Task 4).
3. `set_hidden` na produkcie z seeda ukryłby prawdziwy produkt: funkcja odmawia sluga bez `test-` (Task 1).
4. Uszkodzony JSON trafia do każdego endpointu z treścią — brak jednego w parametryzacji to luka (Task 5 wymienia 9 + notify).
5. Telefon z `+48` i separatorami ma przejść w obu kształtach zamówienia, nie tylko w kasie (Task 3).
