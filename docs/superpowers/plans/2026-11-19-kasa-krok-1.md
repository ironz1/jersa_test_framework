# Kasa, krok 1 — dopasowanie testów do nowej kasy: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pełny zestaw testów zielony na sklepie z gałęzi `feat/payu` (dziś 144 passed, 6 failed), bez osłabiania testów, plus nowy przypadek A-CART-14.

**Architecture:** Zmiany tylko w repo testów, gałąź `feat/payu` (para z gałęzią sklepu). Schemat koszyka dostaje dwa pola; testy „ponad stan” przy zamówieniu przechodzą na scenariusz wyścigu dwóch klientów o ostatnią sztukę; `CheckoutPage` poznaje nowy formularz `/kasa`.

**Tech Stack:** Python 3.12, pytest (+xdist `-n 4`), requests, psycopg 3, Playwright, jsonschema.

**Spec:** `docs/superpowers/specs/2026-11-19-kasa-krok-1-design.md`

## Global Constraints

- Sklep pod testami: `feat/payu` od `eba7b3d`, w Dockerze `docker compose up -d --build --wait`, `127.0.0.1:3100`.
- Każdy test sklepu: marker `regression`, docstring zaczyna się od ID przypadku, wpis w `docs/traceability.json`.
- Własny produkt na test (`product` / `make_product`), nigdy seed; drugi klient przez `make_shop()`.
- Schematy: `additionalProperties: false` zostaje.
- Anty-cel: nie usuwamy sprawdzenia „Brak stanu” przy zamówieniu i nie luzujemy schematów.
- Repo publiczne: bez ścieżek lokalnych i danych osobowych w commitach.

## Review Focus

1. Testy wyścigu (A-ORD-05, D-ORD-05, D-ORD-06) muszą być niezależne przy `-n 4`: każdy ma własny produkt i dwie własne sesje.
2. Asercja stanu w D-ORD-06 musi pokazać, że odrzucone zamówienie A nie ruszyło rozmiaru 36 (stan 5 zostaje 5).
3. Lokator sumy w `OrderPage.total` nie może łapać innych kwot na stronie zamówienia (strona pokazuje teraz zdanie „Całkowita wartość zakupów, wraz z kosztami wysyłki:”).
4. Etykieta „Kod” w starym `CheckoutPage` łapała „Kod pocztowy”; nowe lokatory mają używać pełnych etykiet strony, żeby drugi adres (ukryty) albo przyszłe pole kodu rabatowego ich nie złapały.
5. Komunikat „Dostępnych jest N szt.” zależy od stanu rozmiaru, nie od ilości w koszyku: przy dodaniu narastającym (2, potem 1 przy stanie 2) komunikat to „Dostępnych jest 2 szt.”.
