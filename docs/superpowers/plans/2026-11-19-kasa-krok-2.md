# Kasa, krok 2 — testy kasy, kodów rabatowych i płatności: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Testy kontraktu, API, bazy i jeden E2E dla kasy sklepu z `main`: kody rabatowe, walidacja kasy, suma z dostawą, odpis zamówienia, kwota w powiadomieniu PayU, panel kodów.

**Architecture:** Nowa fixture `make_discount_code` (wiersz w `"DiscountCode"`, sprzątanie po ID) jak `make_product`. `CommerceApi` dostaje metody kasy i rabatu, `checkout_body()` buduje poprawne pole `checkout`. Panel kodów przez `AdminApi` z ciasteczkiem z logowania w przeglądarce (raz na proces). Testy dzielone na pliki wg obszaru.

**Tech Stack:** Python 3.12, pytest + xdist (`-n 4`), requests, psycopg 3, Playwright, jsonschema, zoneinfo.

**Spec:** `docs/superpowers/specs/2026-11-19-kasa-krok-2-design.md`

## Global Constraints

- Sklep pod testami: `main` sklepu z kasą, Docker `docker compose up -d --build --wait`, `127.0.0.1:3100`, `PAYU_MODE: mock`.
- Każdy test sklepu: marker `regression` (`smoke` tylko A-CHK-01), docstring zaczyna się od ID, wpis w `docs/traceability.json`.
- Własny produkt (`make_product`) w każdym teście, który kupuje albo liczy rabat; seed tylko czytany. Kody zawsze z prefiksem `test-` i sprzątane po ID.
- Komunikaty błędów porównywane dokładnie (`{"error": "..."}`, status 400).
- ADR-014: test, który pokaże zachowanie niezgodne ze spec lub decyzją właściciela, **nie** trafia do commita; zapisz go w ledgerze jako `Ruling:` i w lokalnym handoffie dla agenta sklepu (`docs/handoff/`, dopisany do `.git/info/exclude`), a w macierzy nie dodawaj przypadku.
- Repo publiczne: bez ścieżek lokalnych i danych osobowych.

## Review Focus

1. Kody rabatowe są globalne w sklepie: żaden test nie może zależeć od tego, że innych kodów nie ma (lista w panelu filtrowana po własnym kodzie lub ID, nie po długości).
2. „Dziś” w Warszawie ≠ „dziś” w UTC między 23:00 a 01:00: data końca liczona w teście z `ZoneInfo("Europe/Warsaw")`, `endsOn` zapisany jako północ UTC tej daty.
3. Sprzątanie: kody z panelu (utworzone i odrzucone duplikaty) usuwane po ID przez SQL także po nieudanym teście; zamówienia sprząta `make_product`.
4. Zaokrąglenie: `Math.round` w JS zaokrągla ,5 w górę (25 zł × 10% = 2,5 → 3); test oczekuje 3, nie bankierskiego 2.
5. Odrzucona kasa: koszyk zostaje i zamówienia w bazie nie ma; dla kodu nieważnego przy zamówieniu kod schodzi z koszyka (`discountCode == ""`).
